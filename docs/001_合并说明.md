# mach-calculators 合并说明

日期：2026-07-02

## 背景

原仓库中存在两个小包：

- `packages/mach-formulas`：数控加工公式库。
- `packages/mach-calculators`：计算器 schema 和公式适配层。

二者代码量不大，且 `mach-calculators` 对 `mach-formulas` 是上层薄封装。独立发布两个 npm 包会引入额外版本同步和发布维护成本。

## 决策

合并为单个 npm 包：`@usethink/mach-calculators`。

合并后的模块边界：

- `@usethink/mach-calculators/formulas`：公式库。
- `@usethink/mach-calculators/schema`：计算器 schema。
- `@usethink/mach-calculators/adapters`：表单输入到公式输入的适配层。

## 发布策略

该包迁移到 `/Users/dingyuwang/0-X/2-node/mach-calculators`，作为独立 npm 包维护。

发布流程使用 `@usethink/publish-toolkit@0.1.15`，并显式走 npm 路径：

- `npm ci`
- `npm run type-check`
- `npm test`
- `npm run build`
- `publish-toolkit publish --package-manager npm`

关键约束：

- `@usethink/publish-toolkit@0.1.8` 曾在发布阶段优先检测并调用 `pnpm publish`，导致 GitHub Actions 进入 pnpm 路径并触发 `ERR_PNPM_IGNORED_BUILDS`。
- `@usethink/publish-toolkit@0.1.15` 已修复该问题：默认 npm、支持显式 `--package-manager npm`、精确检查 `package@version`、使用临时 npm userconfig 注入认证。
- 本包作为独立 npm 包维护，保留 `package-lock.json` 并使用 `npm ci`，不参与 pnpm workspace 安装链路。
- 首次创建 `@usethink/mach-calculators` 时，GitHub Actions 中的 token 曾返回 E404；本机 `iusethink` owner 登录态可以创建并发布，说明该 E404 是 token/组织新包创建权限问题，不是包内容或 npm 命令问题。
